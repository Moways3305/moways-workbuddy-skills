# 证据与指标设计

## 证据卡

每条关键结论记录 `claim`、`source`、`source_type`、`scope`、`status` 和 `implication`。论坛和社交媒体适合发现关键词、失败模式与替代方案；重要事实回到第一方来源核验。

## 指标分层

| 层 | 示例 | 目的 |
|---|---|---|
| 发现 | 正向触发率、误触发率 | Skill 是否在正确场景出现 |
| 任务 | 任务成功率、关键字段完整率 | 是否完成用户任务 |
| 证据 | 可追溯事实占比、未核实项准确标记率 | 控制幻觉 |
| 效率 | 完成时长、人工修改量、工具调用失败率 | 比较基线 |
| 安全 | 越权、敏感信息、危险动作 | 硬闸门 |
| 运行 | 回归通过率、失败复现率、版本回退时间 | 支持迭代 |

## 指标定义

`指标 = 分子 / 分母 × 100%` 时必须写清分子、分母和排除项。例如：

- 正向触发率 = 正确触发的正向用例数 / 正向用例总数；
- 误触发率 = 错误触发的负向用例数 / 负向用例总数；
- 关键字段完整率 = 已正确填写的必填字段数 / 必填字段总数。

阈值是产品决策，不要伪装成外部标准。标明阈值依据：法规或官方要求、历史基线、风险偏好或试点数据。
