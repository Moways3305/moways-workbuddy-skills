# v0.1.2 独立 Judge 复核

## 结论

第三轮只读终审未发现剩余 P0。代码具备在四类报告齐备、授权评审者确认后生成内部候选包的条件。`runtime pending` 不阻断 `internal-candidate`，但继续阻断 `public-release`。

## 三轮缺陷闭合

第一轮识别并阻断：

- 打包未绑定行为、Judge 和安全闸门；
- 自制校验未覆盖官方 validators 和 `agents/openai.yaml`；
- 项目状态可以用任意值通过；
- symlink 可能把根外文件带入包；
- 打包器缺少自动测试。

第二轮确认上述主链路已修复，并补充：

- 发布状态必须绑定 manifest 版本、源码摘要、四类报告和时间；
- 绝对用户路径必须阻断；
- 包与 SHA256 失败时不能留下半套交付；
- 状态文件应由生成器产生，不靠手工拼写。

第三轮终审结论：

- 未发现剩余 P0；
- 四类报告齐备后可生成内部候选包；
- 公开发布继续阻断。

## 终审后继续收口的 P1

- 四份报告必须各自含 `RELEASE_GATE: PASS`，路径必须互异；
- 生成状态必须显式使用 `--approve`；
- 畸形 `release-status.json` 返回稳定门禁错误；
- 绝对路径扫描覆盖 `C:\Users`、`C:/Users`、`/Users` 和 `/home`；
- ZIP 生成后重新计算包内源码摘要；
- Plugin 根内只允许保留的 `release/` 作为输出目录，其他根内输出被拒绝。

## 证据边界

Judge 为只读静态审查，没有执行宿主触发、安装或公开发布。候选包只适合受控试点，不能写成已完成正式发布。

## v0.1.1 回归边界

v0.1.1 没有新增一轮独立 Judge。此前 Judge 结论仅继承到未改变的 Skill 编排、打包原子性和发布边界；本轮新增的结构化证据解析由 3 类负向自动测试和官方静态校验覆盖。该继承足以支持内部候选回归，不得写成“v0.1.1 已完成新增独立盲评”。

## v0.1.2 回归边界

v0.1.2 showcase 由三名独立验收师傅按匿名 A/B 六项断言复核。候选版三轮均为 6/6、100%；基线分别为 1/6、3/6、1/6，均值 27.8%、总体标准差约 15.7%，候选相对基线提升 72.2 个百分点，三名验收者均推荐候选版。

验收师傅指出首版断言可能被空壳 5/5/3、弱阶段锚点和自报角色白名单绕过。候选随后补充真实用例合同、固定阶段证据映射、根内路径限制、固定角色集合和更多隐私特征；独立回归实跑最终验证器为 19/19 PASS。

此前 Judge 对四个 Skill、打包和发布边界的结论继续沿用。本轮独立复核只证明示范件可理解性、完整性、可验证性和证据诚实性，不替代宿主行为 Judge。
